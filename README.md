# ISP Monitoring — GitHub-only edition

Static GitHub Pages dashboard backed by JSON snapshots generated by GitHub Actions. This repository contains tested software components; it is not yet a production-ready private NMS.

## Architecture and implemented software
- Static HTML/CSS/ES modules in `frontend/`.
- Node.js scanner and processing modules in `backend/`, executed by GitHub-hosted Actions.
- Device credentials are supplied through the Actions secret `ISP_DEVICES_JSON`.
- Snapshot, daily history and history index are versioned under `data/`.
- MikroTik system/PPPoE/interface/queue collection; configurable OLT SNMP and ONU inventory; telemetry, topology, analytics, history and alert engines.
- Onboarding form validates configuration and downloads a secret JSON payload; it does not connect to devices or write GitHub Secrets.

## Privacy gate
The repository is public. The scanner workflow now checks GitHub repository metadata and **fails closed unless the repository is private**. This prevents committing device IPs, PPPoE identifiers, topology and alert data into a public repository. Do not bypass this gate to run customer-data scans.

The static login page is intentionally disabled. GitHub Pages has no server-side authentication in this architecture. Never enter credentials into a browser-only login form or put a GitHub token in frontend JavaScript.

## Device and network boundaries
- OLT ONU discovery requires exact vendor/model/firmware MIB OIDs; no OIDs are invented.
- GitHub-hosted runners generally cannot reach private RFC1918 ISP addresses. The software tests use simulated samples; real MikroTik/OLT hardware connectivity has not been verified.
- No local machine, self-hosted runner or external backend is part of this design.

## Validation
Run from the repository root: `npm test` and `npm run validate`.
