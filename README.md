# ISP Monitoring — GitHub-only edition

A static GitHub Pages dashboard backed by JSON snapshots generated by GitHub Actions. The current scanner has real MikroTik RouterOS API and basic OLT SNMP system-status adapters; coverage is not yet a complete NMS.

## Architecture
- **Frontend:** static HTML, CSS and ES modules in `frontend/`.
- **Scanner:** Node.js scripts in `backend/`, executed by GitHub-hosted Actions.
- **Configuration:** repository Actions secret `ISP_DEVICES_JSON`; never commit credentials.
- **State:** versioned JSON snapshot in `data/devices-status.json` and append-only daily JSONL history under `data/history/`.
- **Hosting:** GitHub Pages deployment workflow.

## Device onboarding
Open `frontend/add-device.html` on the deployed Pages site. The form validates a MikroTik or OLT configuration and downloads a JSON secret payload. It does **not** connect to hardware or write to GitHub. Copy the payload into repository Settings → Secrets and variables → Actions as `ISP_DEVICES_JSON`, then run **GitHub-Only On-Demand ISP Scanner** from Actions.

GitHub Pages is read-only. Never put a GitHub token in browser JavaScript. The scanner run is the only current hardware connection test.

## Development and validation
```sh
cd backend
npm install
npm test
npm run validate
```

## Current boundaries
- MikroTik: system resource and active PPPoE sessions are currently collected.
- OLT: basic SNMP system identity/uptime only; ONU discovery and optical metrics are not implemented.
- Switch/router generic adapters, live traffic graphs, authentication, alerting and topology are not complete.
- GitHub-hosted runners can scan only devices reachable from their network environment. No self-hosted runner is part of this project architecture.
